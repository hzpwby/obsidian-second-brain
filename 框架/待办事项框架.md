## 一、待办框架文件架构

```
待办事项/
├── 工作待办.md          ← 工作执行：日常工作中具体要做的事
├── 系统迭代待办.md       ← 个人成长：健身、练琴、阅读、学新技能
├── obsidian架构待办.md ← 系统维护：Obsidian 优化、知识库调整
└── 起念.md             ← 行动的想法：脑内冒出的点子、灵感，不定日期，成熟后分流
```

> 具体文件列表以实盘为准。AI 操作时先读取 `待办事项/` 最新目录结构，不以本框架中的静态示例为准。

## 二、数据流向

```
创建待办（设 📅）  →  到期自动出现在日复盘
日复盘勾选完成        →  自动进入「今日完成」列表
                       →  待办文件同步标记完成
```

**不需要手动复制、粘贴、搬运任何数据。** Tasks 负责自动查询，每天只在日复盘一个文件中完成所有操作。

**模板文件**：`模板/日志模板.md`，用 Templater 每天自动生成到 `日志/日复盘/YYYY-MM-DD.md`。

> 日复盘模板的完整结构定义、Tasks 查询块详解、自动归集机制与 CSS 配置，详见 [[复盘迭代框架#四、日复盘：每日数据采集]]。

## 三、待办笔记内容

### Tasks 语法速查

```
- [ ] 任务描述    📅 截止日期 优先级
```

| 字段 | 写法 | 说明 |
|------|------|------|
| 截止日期 | `📅 YYYY-MM-DD` | 最终必须完成的日期。逾期自动出现在日复盘「逾期未完成」 |
| 优先级 | `⏫` 最高 / `🔼` 高 / 无 普通 / `🔽` 低 | |
| 重复 | `🔁 every day` / `every week` | |
| 依赖 | 右键任务 → Before this / After this | 前置没完成，后置不会出现在日复盘 |

**核心原理**：写好待办项并设 📅 后，Tasks 自动在对应日期将其归集到日复盘中。不需要手动复制或搬运。

### 文件标准结构

每个待办文件的标准结构＝**顶部 Tasks 汇总块＋大标题＋分组勾选项**。**模板文件**：`模板/待办事项模板.md`——新建待办文件直接套用，把汇总块里的 `{本文件名}` 换成实际文件名（与文件同名、不含 .md）。

汇总块写法（未完成的全部汇总在文件顶部，勾选完成即从汇总消失，原句保留在分组里）：

````
```tasks
path includes 本文件名
not done
sort by priority
```
````

### 任务行示例

分组内按如下格式书写。以 `工作待办.md` 为例：

```markdown
## 工作待办

- [ ] 整理客户反馈，写周报    📅 2026-06-03 🔼
- [ ] 准备项目评审材料    ⏫ 📅 2026-05-20
```

其余文件（系统迭代待办、obsidian架构待办、起念）格式相同，替换分类标题即可。
