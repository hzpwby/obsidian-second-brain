## 一、菜谱框架文件架构

```
个人迭代/菜谱/
├── 菜谱目录/              ← Bases 管理入口，每分类一个 .base
│   ├── 荤菜.base          ← imageField: cover
│   ├── 素菜.base          ← imageField: cover
│   └── ...               ← 汤、早餐、餐后甜点、主食
├── 菜谱附件/               ← 每道菜一个子文件夹，存封面 + 用料图 + 步骤图
│   ├── 辣椒炒肉/
│   └── ...
├── 荤菜/                   ← 各分类目录，存对应菜谱 .md
├── 素菜/
├── 汤/
├── 早餐/
├── 餐后甜点/
└── 主食/

模板/菜谱模板.md          ← 含 YAML 头（菜名、分类标签、cover）
```

> 具体文件列表以实盘为准。AI 操作时先读取 `个人迭代/菜谱/` 最新目录结构，不以本框架中的静态示例为准。

## 二、菜谱完整生命周期

> 一道菜从建立到持续优化的四个阶段。
### 1. 创建
按「三、创建步骤」新建菜谱笔记，含附件、YAML、Bases 配置。详见下一节。
### 2. 使用
做菜时打开对应菜谱笔记，按用料和步骤操作。
### 3. 反馈
每日复盘时在「菜谱」板块记录当日做菜体验。复盘后，你会在菜谱对话框口述调整需求，AI 直接优化对应菜谱笔记。
### 4. 迭代
根据实际做菜体验持续调整用料、步骤、备注。菜谱笔记是活的，每次做菜都是迭代机会。

## 三、创建步骤

> 每新增一道菜，按以下步骤操作。

### 步骤 1：创建附件目录

在 `个人迭代/菜谱/菜谱附件/` 下新建以菜名命名的文件夹，所有这道菜的图片（封面、用料图示、步骤图示）统一放这里。

```
个人迭代/菜谱/菜谱附件/
├── 辣椒炒肉/
│   ├── 辣椒炒肉.jpg
│   ├── 五花肉.jpg
│   ├── 螺丝椒.jpg
│   ├── 步骤1.jpg
│   └── ...
└── 番茄炒蛋/
    ├── 番茄炒蛋.jpg
    ├── 番茄.jpg
    ├── 鸡蛋.jpg
    ├── 步骤1.jpg
    └── ...
```

**图示链接约定**：用料和步骤的图示列使用 `[[个人迭代/菜谱/菜谱附件/菜名/图片.jpg|短名]]` 格式，如 `[[个人迭代/菜谱/菜谱附件/辣椒炒肉/五花肉.jpg|五花肉]]`，显示为短名而非完整路径。

### 步骤 2：从模板创建笔记

用 `模板/菜谱模板.md` 新建笔记，文件名 `{菜名}.md`（如 `辣椒炒肉.md`），放在对应分类目录（详见 [[#一、菜谱框架文件架构]]）：

| 分类 | 目录 | Bases 卡片视图 |
|------|------|------------------|
| 荤菜 | `个人迭代/菜谱/荤菜/` | `菜谱目录/荤菜.base` |
| 素菜 | `个人迭代/菜谱/素菜/` | `菜谱目录/素菜.base` |
| 汤 | `个人迭代/菜谱/汤/` | `菜谱目录/汤.base` |
| 早餐 | `个人迭代/菜谱/早餐/` | `菜谱目录/早餐.base` |
| 餐后甜点 | `个人迭代/菜谱/餐后甜点/` | `菜谱目录/餐后甜点.base` |
| 主食 | `个人迭代/菜谱/主食/` | `菜谱目录/主食.base` |

### 步骤 3：填写 YAML 头

模板已含 frontmatter，填充以下三个字段：

```yaml
---
菜名: 辣椒炒肉
分类标签:
  - 家常
  - 荤菜
cover: "[[个人迭代/菜谱/菜谱附件/辣椒炒肉/辣椒炒肉.jpg]]"
---
```

`cover` 使用 wiki-link 格式指向步骤 1 创建的附件目录下的封面图片。

### 步骤 4：确认 Bases 封面配置

对应分类的 `.base` 文件需包含以下三行，卡片视图才能显示封面：

```yaml
imageField: cover
image: note.cover
imageAspectRatio: 1.45
```

荤菜和素菜的 `.base` 已配置。新增其他分类时需同步加上。

### 步骤 5：填入内容

用料表格 → 步骤表格 → 备注。

**配料统一规则**：所有调料（生抽、老抽、蚝油、盐、味精、料酒、白糖等）在用料表格中**集中写一行**「配料」，备注列罗列调料名即可。不放用量（步骤中已说明），不分散为多行。装饰性辅料（白芝麻、小葱等）不受此规则限制，可单独列出。
