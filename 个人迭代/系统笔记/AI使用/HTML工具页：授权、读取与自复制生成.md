# HTML工具页：授权、读取与自复制生成

## 核心观点

**网页（含双击打开的本地 HTML）读本地文件，只有「文件授权」一条正规通道：路径不等于权限、把路径告诉脚本没用、必须用户亲手在授权弹窗里选定。所有读取调用必须带超时——环境的读取会无声卡死。授权按「浏览器+来源」记在浏览器本地，一次授权终身有效、跨文件共享、关机重启无关。**

## 详细内容

### 背景

2026-10-13 每日任务看板（单文件 HTML）做「一键滚日」：扫当天日志 md → 生成明天看板。授权与读取翻来覆去修了一整轮才收敛。适用对象：一切「网页读本地文件 / 生成本地文件」的单文件工具（每日看板同族）。

### 浏览器安全模型（第一约束，先认清再动手）

- file:// 页面读本地文件只有一条正规通道：文件授权 API（目录授权 showDirectoryPicker / 单文件授权 showOpenFilePicker）。**路径只是字符串——把路径写进脚本毫无用处**，必须用户在弹窗里亲手选定。
- fetch/XHR 读本地路径：被浏览器直接禁掉，别试。
- 授权按「浏览器+来源（file://）」记在浏览器 IndexedDB：**跨文件共享**（A 文件授权过，B 文件直接用）、**关机重启无关**；**换浏览器 / 换电脑 / 清浏览器数据 = 各自重来一次**。

### 环境差异（最大变量）

同一份代码：标准 Edge 全链通；某些内置浏览器/特殊环境只实现一半——实测案例：文件夹授权弹窗报「包含系统文件」假错（夹内 139 个文件全是普通 md）、枚举正常但读内容卡死。**对策：**

- 所有授权/读取调用包 withTimeout（3~10 秒），卡死当失败处理，流程必往下走；
- 降级链：目录授权 → 单文件选择 →（最后手段）粘贴；
- 报错带「卡死定位」（哪一步、哪个接口），不做无声失败。

### 接口版本（旧接口陷阱）

- 目录句柄的旧读取 getFile **已在现代 Edge 移除**（调用即 TypeError: not a function）。原型检测可诊断：`FileSystemDirectoryHandle.prototype.getFile` 为 false 即环境无此方法。
- 正规写法：`getFileHandle(文件名)` 拿文件句柄 → `句柄.getFile()` → `.text()`。
- 教训：v1 测试页已经显示「存在于原型: false」，当时只当诊断数据，没意识到看板代码还在用死接口——**测试页的每个异常输出都要回溯到代码**。

### 流程设计原则

- **数据源方向**：日志 md 是上游数据源；不从上一份产物继承（特例会污染主流程）。
- **自复制**：页面读自身源码（style / shells 骨架 / 脚本文本）+ 新数据 → 拼出完整新文件；单文件自包含，链条永不断。
- **降级确定性**：环境坏一次就记住（localStorage 标记），不再反复弹坏弹窗；用户取消授权=中止，静默退出不骚扰。

### 仪式触发（按自然日+文件记 flag）

- flag 键 = ritual_前缀_今天日期：同一天第二次打开不触发；**换日自动再触发**（使用当天的仪式感）；文件过期（隔天再开）永不触发。
- 节奏=生成当晚一次（确认）+ 使用当天一次（仪式感），共两次——与定级仪式「昨夜定、今日行」的节奏一致。

### 流程级教训（修补纪律）

- **大段切片修补会吞函数**：用「起点锚→终点锚」整段替换时，中间的无关函数可能被一起吃掉。每轮改动后必须跑**函数定义完整性核对**（列调用清单 vs 定义清单）——本次实锤：buildFile 与整个仪式向导被吃掉，症状=读取成功后静默中断 + 仪式永不触发。
- **对话里附带的文件内容可能是旧快照**：排查以磁盘当前文件为准，别拿早前 Read 到的版本当现状。
- **先做最小复现测试页**：把「浏览器能力问题」和「页面代码问题」分开验证——一个几十行的裸调用测试页，一次就终结了来回猜。

### 日常使用（定稿后的完整链路）

1. 白天/晚上：在 Obsidian 写今天日志（「明日任务」区定级+增量、改进项带明天日期）；
2. 打开今天看板 → 点「新一天」→ 自动扫日志 → 保存框选桌面 → 明天看板生成；
3. 当晚打开明天看板（仪式第一遍）→ 明早打开（仪式第二遍）→ 用；
4. 种子模板躺在模板夹：链条哪天断了，双击它就能从头再来。
