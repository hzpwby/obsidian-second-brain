# 本地PDF批量转md（MinerU）

## 核心观点

**扫描版 PDF 是图片，AI 逐页读图既烧钱又慢——让本机 OCR 一次转成 Markdown，任何 AI 直接读文字层。** 转换成本一次性、本地、零 AI token；转换质量已经双验收（题目零丢失、公式转 LaTeX、插图自动抽出）。换任何一个对话 AI，把本文的命令块发给它即可续用，不依赖特定 AI 的记忆。

---

## 它是什么、装在哪

- **MinerU**（上海 AI 实验室开源）：PDF→Markdown 命令行工具，含 OCR/公式/表格识别
- 装在本机 **`<MinerU安装目录>\venv`**（独立 Python 虚拟环境，不污染系统；不想要了删该文件夹即整体卸载）
- 模型已缓存在 C 盘 `~/.cache/modelscope`（约 1G，魔搭源下载，无需翻墙）
- 硬件要求：6GB+ 显存的 N 卡，或纯 CPU（慢一些但完全可用）

## 怎么用（把这段原样发给任何 AI）

```
用本机 MinerU 把 PDF 转成 markdown，命令模板：
MINERU_MODEL_SOURCE=modelscope <MinerU安装目录>/venv/Scripts/mineru.exe -p "<PDF路径>" -o "<输出目录>" -b pipeline -m ocr -l ch

参数说明：
-b pipeline  必须指定（默认后端吃显存，pipeline 才是 6G 显存能跑的）
-m ocr       扫描件模式（无文字层的 PDF 必须）
-l ch        中文
-s N -e M    可选：只转第 N~M 页（从 0 起算）
输出：<目录>/<PDF名>/ocr/<PDF名>.md ＋ images/ 文件夹（全部插图）

注意事项：
1. 输出目录放桌面（用户约定，不放深层目录）
2. 首次运行会自动下模型到 ~/.cache/modelscope，之后有缓存
3. 切页范围时，边界先用转换出的文字验证（扫描版的页眉页脚会骗人）
4. 已知小疵：图标文字偶尔混入句子、极少数段落乱序——AI 读 md 时注意甄别
```

## 典型场景

| 场景 | 做法 |
|------|------|
| 给 AI 喂练习册/试卷题源 | 先转 md，再让 AI 读 md（**禁止**让 AI 对扫描件逐页读图——资源红线） |
| 只要某几节 | 先用页范围参数小转，验证边界后再定范围 |
| 题目配图 | 转换结果 images/ 里有全部插图，按需拷贝、嵌入题型卡片 |
| 整本大 PDF 转换卡死 | OCR/MFR 阶段偶发挂起——**拆成几块（按页段）分别重试**即可通过（2026-09-13 二下实践：拆块后全套转完） |
| 密集页速度 | GPU 密集页约 2 分钟/页（6GB 显卡）；长本先估时，别让转换阻塞建卡（见 [[跑长期任务：防的是卡死，不是做错]]） |

## 为什么有效

- **绕开读图成本**：OCR 在本机 GPU/CPU 跑，AI 只碰文字层，成本从"每页一次视觉调用"降为零
- **跨 AI 可迁移**：工具在本地，不绑任何对话产品的账号或插件；一个命令块就是全部操作手册
- **零风险试错**：独立 venv，删文件夹即回退（[[用沙盒模拟，降低AI操作风险]]的隔离模式）
