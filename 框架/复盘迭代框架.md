## 设计哲学：日志为什么存在

> 2026-08-21 回轨夜汇总。本节是已有规则的索引地图，不重定义——唯一事实源在各条的出处里。

**日复盘的九个目的**（1-4 是你说出口的，5-9 是系统里写着但容易忘的）：

| #   | 目的          | 一句话                    | 出处                |
| --- | ----------- | ---------------------- | ----------------- |
| 1   | 每天有总结       | 固定四段（结论/完成的/改进/明日任务）＋按需正向    | 本框架·六             |
| 2   | 进步点与明天优化点   | 判断列评估＋改进项 📅 明天，跨天闭环   | 本框架·四             |
| 3   | 笔记可溯源       | 所有分流产出双链回指当日日志         | 本框架·六·反思分流        |
| 4   | 量化人生轨迹      | Tracker 图表的唯一数据源，断更即断线 | 本框架·二             |
| 5   | 上层复盘的原料     | 日→周→月→年，分层总结不搬运        | 本框架开篇             |
| 6   | 系统进化的裁判     | 维护模式两条解锁路径都靠日志证据       | [[总论框架#四、维护规则]]   |
| 7   | 状态底线守护      | 状态滑坡被看见（8月实证）          | [[最低系统使用指南]] 状态分级 |
| 8   | AI 协作的上下文底座 | 框架给 AI 全局，日志给 AI 今天    | [[最低系统使用指南]] 开篇   |

**档案模型**（2026-08-21 定）：

- 需要沉淀的，写时已经反思分流进笔记或待处理——**没沉淀的就是档案，随时可查可溯**
- 沉淀三通道：**即时分流**（反思分流规则）＋**定期开采**（周/月复盘从聚合回收规律——「状态是最底层的东西」就是三个月聚合才显形的实例）＋**长进身体**（技能与规律兑现于人，日志是路径记录）
- 因此也不焦虑"没沉淀"，有沉淀价值，当时就沉淀了

## 一、复盘系统文件架构

```
日志/
├── 日复盘/                    ← 每天一篇，由 `模板/日志模板.md` 自动生成
│   ├── 2026-05-28.md
│   └── ...
├── 周复盘/
│   └── 2026年/
│       └── 2026年6月/
│           ├── 2026年6月第1周.md
│           └── ...            ← 按周预建，随时间推进
├── 月复盘/
│   └── 2026年/
│       ├── 2026年6月.md
│       └── ...                ← 按月预建，随时间推进
├── 年复盘/
│   └── 2026年.md              ← 年末填写
└── 复盘目录/                  ← Bases 管理入口
    ├── 周复盘与规划目录.base   → 按年→月→周卡片视图查看所有周复盘
    │   └── 周复盘与规划目录/
    │       ├── 2026年6月.base
    │       ├── ...（按月分）
    │       └── 2026年12月.base
    ├── 月复盘与规划目录.base   → 按月卡片视图查看所有月复盘
    │   └── 月复盘与规划目录/
    │       └── 2026年，月复盘与规划目录.base
    └── 年复盘与规划目录.base   → 按年卡片视图查看年复盘
```
> 具体文件列表以实盘为准。AI 操作时先读取 `日志/` 最新目录结构，不以本框架中的静态示例为准。

**生成方式**：日复盘用 Templater 从 `模板/日志模板.md` 自动生成。周/月/年复盘空文件按 `模板/周复盘模板.md`、`模板/月复盘模板.md`、`模板/年复盘模板.md` 预建，到时间直接填写。

**Bases 管理**：每个 `.base` 文件按 `file.folder` 筛选对应目录，卡片视图按 `file.name` 排序展示。

## 二、Tracker：数据可视化

### 配置位置

| 位置 | 图表 | 类型 |
|------|------|------|
| 🏠Home.canvas | 健身热力图 | `searchType: task.done`, `month: circle` |
| 🏠Home.canvas | 练琴热力图 | `searchType: task.done`, `month: circle` |
| 🏠Home.canvas | 体重折线图 | `searchType: text`, `line` |
| 🏠Home.canvas | 睡眠折线图 | `searchType: text`, `line` |
| 日复盘·健康数据 | 体重进度汇总 | `searchType: text`, `summary` |

### 配置详解

#### 健身热力图

**数据源**：日复盘 `系统迭代` 下的 `- [x] 健身打卡` checkbox。

> 记录词带"打卡"（2026-09-02 定）：task 类型的 searchTarget 只做子串匹配且不支持正则——明日任务里"健身：xxx"任务被勾选时会让头一天的文件误亮热力图。记录词（健身打卡）与任务词（健身：）分开后彻底避开。

**文字记录**：日复盘 `迭代复盘·健身` 板块手动记录当日练了什么项目、顺序、重量，链接到 `个人迭代/系统笔记/健身/`。与热力图互补——热力图看频率，文字看内容。

```tracker
searchType: task.done
searchTarget: 健身打卡
folder: 日志/日复盘
startDate: 2026-05-01
datasetName: 健身
fixedScale: 0.7
month:
    mode: circle
    color: green
```

| 参数                      | 说明               | 注意事项                      |
| ----------------------- | ---------------- | ------------------------- |
| `searchType: task.done` | 读取 checkbox 完成状态 | `task.done` 有互动性，`text` 无 |
| `searchTarget: 健身打卡`    | 匹配 checkbox 文字   | 必须与日复盘中的文字完全一致；task 类型不支持正则 |
| `mode: circle`          | 月历圆圈热力图          | 不加这行不渲染                   |
| `startDate`             | 必填               | 不加这行不渲染                   |
| `fixedScale: 0.7`       | 缩放至 70%          | 调这个可以控制卡片内图表大小            |

#### 阅读热力图

**配置同健身**，唯一区别：`searchTarget: 阅读打卡`，`color: orange`。

#### 体重折线图 + 汇总

**数据源**：日复盘 `**体重**: 62.0` 格式的行。

**折线图**（Home.canvas）：
```tracker
searchType: text
searchTarget: '\*\*体重\*\*: ?(?<value>[0-9]+(\.[0-9]+)?)'
folder: 日志/日复盘
startDate: 2026-05-28
datasetName: 体重
fixedScale: 0.7
line:
    title: 📈 体重变化趋势（kg）
    lineColor: '#4CAF50'
    yMin: 50
    yMax: 80
    showPoint: true
    xAxisTickLabelFormat: YY-M-DD
    xAxisLabel: ' '
    yAxisLabel: ' '
```

**进度汇总**（日复盘内嵌）：
```tracker
searchType: text
searchTarget: '\*\*体重\*\*: ?(?<value>[0-9.]+)'
folder: 日志/日复盘
startDate: <% tp.date.now("YYYY-MM-DD") %>
endDate: <% tp.date.now("YYYY-MM-DD") %>
datasetName: 体重
summary:
    template: "当前进度 {{(sum()-61)/2*100::.1f}}%"
```

| 参数                            | 说明                           |
| ----------------------------- | ---------------------------- |
| `(?<value>[0-9]+(\.[0-9]+)?)` | 匹配整数或小数，如 58 和 58.5          |
| `yMin: 50`                    | Y 轴最小值                       |
| `yMax: 80`                    | Y 轴最大值                       |
| `sum()`                       | 取当日值（因为只有一天的数据）              |
| `(sum()-61)/2`                | 目标 63kg，起始 61kg，差距 2kg       |

#### 睡眠折线图

**数据源**：日复盘 `**睡眠时长**: 7` 格式的行。

```tracker
searchType: text
searchTarget: '\*\*睡眠时长\*\*: ?(?<value>[0-9]+(\\.[0-9]+)?)'
folder: 日志/日复盘
startDate: 2026-05-28
datasetName: 睡眠
fixedScale: 0.7
line:
    title: 📈 睡眠时长趋势（小时）
    lineColor: '#2196F3'
    yMin: 0
    showPoint: true
    xAxisTickLabelFormat: YY-M-DD
    xAxisLabel: ' '
    yAxisLabel: ' '
```

### 常见排查

| 问题 | 原因 | 检查 |
|------|------|------|
| 热力图不渲染 | 缺少 `startDate` 或 `mode: circle` | 两者必须同时存在 |
| 折线图空白 | `folder` 路径不对、无数据 | 确认路径 `日志/日复盘`，确认有对应格式的数据 |
| 正则不匹配 | 空格、小数、无值 | 用 `?` 让空格可选；整数用 `[0-9]+`，小数用 `[0-9]+(\\.[0-9]+)?` |
| 汇总数字不对 | `endDate` 范围问题 | `endDate` 是否包含了目标日期范围 |
| 新加 checkbox 不显示 | 文字不一致 | `searchTarget` 必须与 checkbox 文字完全一致 |
| 月历范围不显示 | 数据不在范围内 | 检查 `startDate` 是否早于第一条数据，月复盘是否跨月 |

## 三、周/月/年复盘：阶段性反思

> 三份模板独立放在模板夹（单一事实源，2026-10-12 起）：`模板/周复盘模板.md`、`模板/月复盘模板.md`、`模板/年复盘模板.md`——本框架只讲节奏与用法，不再内嵌模板全文。空文件已按模板预建，到时间直接填写；周/月/年无动态变量，手动填入即可（日复盘有自动化需求，才走 `模板/日志模板.md` + Templater）。

### 周复盘

**模板**：`模板/周复盘模板.md`——摊图·现状四问 → 本周目标表 → 日推进预估 → 本周完成／反思／下周方向。

**节奏**：每周末花 10-15 分钟填写。先摊图（情境四问）再定目标；数据回看放「本周完成/反思」侧——Tracker 趋势、级别分布、增量兑现率。

**呈现规范（10-12 定）：达标率、判断、结论一律用表格，不用段落堆砌**——便于一眼扫读。

**创建**：已预建，文件名格式 `2026年X月第N周.md`。

### 月复盘

**模板**：`模板/月复盘模板.md`——摊图·现状 → 资金双栏表 → 本月方向表 → 本月完成／反思／下月方向。

**节奏**：每月底填写。先摊图，再对照月初方向看完成度，校准下月目标。

**创建**：已预建。

### 年复盘

**模板**：`模板/年复盘模板.md`——总方向 → 层面表（年度要优化的方向逐行列：方向一/二/三…）→ 各方向详细情况（一/二/三…）→ 年末复盘。2026 年已有初版实例（工作/基础迭代/学习/生活节奏即当年所填方向）。

**节奏**：年初定方向 + 年末填复盘。
## 四、日复盘：每日数据采集

### 结构

由 `模板/日志模板.md` 定义，Templater 填充日期变量：

```
## 📋 今日任务          ← Tasks: happens today, not done
## ⚠️ 逾期未完成        ← Tasks: due before today
## ✅ 今日完成           ← Tasks: done on 当日
## 系统迭代             ← 健身/练琴 checkboxes（Tracker 读取）
## 📊 健康数据           ← 体重 Tracker summary, 睡眠时长, 清醒感受
## 💰 资金              ← 攒的钱, 流动资金
## 迭代复盘             ← 📚学习, 🏋️健身, 🎵音乐, 🍳菜谱（手动记录）
## 每日复盘             ← 复盘引导语 + 改进 + 明日任务（AI 协助生成）＋ 定级仪式（明天几级＋增量）
```
新增迭代项目时：在日复盘模板加 checkbox / text 行 → 在 Home.canvas 加对应 Tracker 块 → 更新 [[#二、Tracker：数据可视化]]
### 手动部分

| 板块 | 内容 | 用途 |
|------|------|------|
| 清醒感受 | 文字描述 | 睡眠质量主观记录 |
| 迭代复盘·学习 | 文字记录当日学习/主业干了什么 | 细节放进对应体系的笔记，日志只做当日记录 |
| 迭代复盘·健身 | 表格记录每组动作、重量、次数 + 双链 | 回链健身系统笔记，长期看进步趋势 |
| 迭代复盘·音乐 | 练琴内容 + 双链 | 回链音乐系统笔记 |
| 迭代复盘·菜谱 | 做饭内容 + 双链 | 回链菜谱笔记 |
| 每日复盘 | AI协助整理的当日总结与反思 | 自由文字，提炼后分流至知识层 |
| 资金 | 攒的钱 / 流动资金 | 手动更新数字 |

> 健身和音乐暂无附件需求（数据全部通过日复盘文本记录）。
### 自动化部分（无需手动）

| 板块    | 机制                       | 说明                                      |
| ----- | ------------------------ | --------------------------------------- |
| 今日任务  | Tasks `happens today`    | 所有 📅 为今天的待办自动出现                        |
| 逾期未完成 | Tasks `due before today` | 过期未勾选的自动标出                              |
| 今日完成  | Tasks `done on 当日`       | 今天勾选完成的自动列出                             |
| 系统迭代  | checkbox `- [ ]`         | 勾选后 Tracker 读取 `task.done` 生成热力图        |
| 体重    | `**体重**: X`              | Tracker 用 `searchType: text` 正则匹配，生成折线图 |
| 睡眠    | `**睡眠时长**: X`            | 同上，生成折线图                                |

### Tasks 查询块详解

**今日任务**：
````
```tasks
happens today
not done
sort by priority
```
````
- `happens today`：所有 📅 为今天的未完成任务
- `not done`：只显示未完成
- `sort by priority`：按优先级排列

**逾期未完成**：
````
```tasks
due before today
not done
sort by priority
```
````
`due before today`：截止日期已过但还没勾选的任务。

**今日完成**：
````
```tasks
done on <% tp.date.now("YYYY-MM-DD") %>
```
````
`<% tp.date.now(...) %>` 是 Templater 变量，生成时自动替换为当天日期。

### 自动归集原理

所有待办文件中写了 `📅 2026-06-01` 的任务，到了 6 月 1 日自动出现在当日复盘的「今日任务」中。勾选完成后，在待办文件中同步标记为完成，同时在日复盘的「今日完成」中列出。

### 每日复盘改进项自动流转

每日复盘底部的「改进」区使用 Tasks 复选框指向明天日期：

```
- [ ] 11:30前睡觉 📅 2026-06-05
```

当天写完后，第二天日志的 Tasks 查询自动归集该改进项到「今日任务」。勾选后进入「今日完成」，形成跨天闭环——不需要手动搬运或复制。

## 五、新增迭代项目步骤
当需要追踪一个新的长期迭代项目时（如：每日阅读、冥想），按以下步骤：

#### 步骤 1：确定采集方式

| 类型 | 采集方式 | 适合场景 |
|------|---------|---------|
| 是否做了 | checkbox `[x]` | 只需知道做没做（健身/练琴） |
| 数值记录 | `**标签**: X` | 需要记录数值（体重/睡眠/推进份数） |

#### 步骤 2：在日复盘模板添加采集入口

打开 `模板/日志模板.md`：

- **checkbox 类型**：在 `系统迭代` 区域加一行 `- [ ] 新项目名`
- **数值类型**：在对应区域加一行 `**新标签**: `

#### 步骤 3：添加 Tracker 配置

- **热力图**：复制健身的 Tracker 块，改 `searchTarget`、`datasetName`、`color`
- **折线图**：复制体重的 Tracker 块，改 `searchTarget`、`datasetName`、`lineColor`、`title`
- **汇总**：在日复盘模板对应区域插入 Tracker 块

#### 步骤 4：存放位置

询问用户需要放在日复盘模板里还是Home.canvas
#### 步骤 5：更新本框架

在迭代项目总览表加一行，在配置详解加对应代码块。
## 六、日复盘：每日复盘总结

### 新建日复盘

1. Templater 从 `模板/日志模板.md` 插入模板
2. 文件名设为 `YYYY-MM-DD.md`，存入 `日志/日复盘/`
3. 模板自动填充当天日期到 `done on` 和 `startDate`/`endDate`

### 每日总结怎么做：交给「每日复盘」skill

对话流程（口述→扫描整理→一次一问收敛→收尾→落笔自查）由「每日复盘」skill 执行——库内事实源 `个人迭代/系统笔记/AI使用/skill/每日复盘/`。本框架只规定写什么：板块与写作要求见下方「每日复盘写作结构」，产出分流见「反思分流」；定级仪式与级别细则的唯一事实源：[[最低系统使用指南#状态分级（重启指标）]]。

### 每日复盘写作结构

每日复盘不固定模板，但有以下共性板块，根据当天情况组合使用：

**固定板块（结论/完成的/改进/明日任务每天必写）：**

**结论**

| 要点 | 规则 |
|------|------|
| 定调短语 | 第一行给今天起个名（如"内耗夜·模板突破日"——今天好还是不好、主题是什么） |
| 因果链 | 下面按当天实际写**"因为什么→所以什么"的因果链**——谁导致谁、转折在哪、最核心的一个原因，条数看着当天的信息定 |
| 自检 | **不在结论里打分打勾（✅❌只活在表格），不复述完成表里的行**——结论讲"今天怎么回事"，表格记"每项做得怎么样"；写完自检：哪条只是表格某行换衣服就删 |

**完成的**

| 要点   | 规则                                                                                                                                                                                                                         |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 表格   | 维度 · 实际 · 判断，逐维度评估不是罗列。                                                                                                                                                                                                    |
| 维度   | 完成表**不复述计划内已完成**——级数/增量里完成的部分，「✅ 今日完成」查询已自动归集，不再列举。表格列两样：①**计划外完成的事**——今天临时多干的、昨天没排到的；②**没完成的**——级数/增量里欠的账逐项列行（推到明天的任务不会进任何查询，不在逾期也不在完成，当天确实没完成只有这里看得见）。③**级数汇总行固定必列（位置：表格首行，2026-10-15 定）**：欠账已在②逐项列出，汇总行只简单点名哪几项没完成——级数里有一项没完成→「级数」行打 ❌；全部完成→✅。**睡眠锚判定注（2026-10-15 定）：以「入睡时间」为达标要件（22:00 线）——时长够不作抵扣、照记**。**勾选按当天（2026-10-18 定）：总结完确定今晚 22:00 睡，睡前勾完成；日志「睡眠时长 / 清醒感受」填前夜——昨晚睡眠＝今天启动的开始，两者不混用** |
| 判断符号 | ✅ 达标 / ❌ 未达（部分完成不用折扣标记——能计数的写 ✅ n/m，不能计数的直接 ❌）/ ↗ 确实进步——比之前明显进步时**单独用**，实际列把对比列出来（如睡眠：前几日 6h/7h/4h，今日 9h），进步怎么来的看得见 / — 无可评估（如未定级）                                                                                         |

**改进**

| 要点 | 规则 |
|------|------|
| 写法 | 从今天根因出发，1-3 条修正措施。Tasks 复选框 📅 明天 |

**明日任务**

| 要点 | 规则 |
|------|------|
| 写法 | 明天的增量推进项。改进区已列的不再重复。Tasks 复选框 📅 明天。 |
| 定级仪式落笔 | 写「明日状态：X级」并把对应级别清单整块复制逐项勾选（清单见 [[最低系统使用指南#状态分级（重启指标）]]，一级生存/二级生活/三级训练/四级满配），增量单列一条——只写"启动二级"四个字不算落笔，要把二级的 8 项内容整块放进明日任务。写完当晚可一键滚出明天看板（见[[#七、每日任务推进HTML看板]]） |

**按需板块（根据当天情况选择）：**

> 触发规则（2026-09-26 定）：某类情况**连续出现两次**时，从当天起固定记录对应板块，让状态可持续追踪（如头痛连续出现 → 身体感知转为每日固定记录，直到情况消失）；单次偶发仍按需，可不记。
> 板块标题在日志里用当天的具体主题名（如「心脏信号」「核心教训」），上表是归类参考菜单、不是封闭清单——当天有值得单独说的主题，起名写一节即可。
> **板块会生长**：按需板块不是一成不变的——当天复盘冒出新板块的想法时问用户一句，用户认可就保存进本表（菜单随实践生长，比如以后出现新的可对比的系列），不认可就只留在当天日志里，不用管。

| 板块 | 什么时候用 |
|------|-----------|
| 根因 | 问题反复出现，需要深挖原因时 |
| 身体感知 | 身体状态有特殊变化，或精力有明显波峰波谷、值得总结规律时 |
| 核心突破 | 当天有重大进展，值得单独叙述时 |
| 正向（损失重估） | 当天有 ❌/— 行或失败事件可重估时——只写“这笔烂账买回了什么”（教训的价值、失败换来的需求、意外的认知收获），**禁写原因**（原因归结论因果链）；没有可重估的就不写 |

**写作原则：**

1. 先有感受，后有结构——不要对着栏目填空。先让当天真实的情绪和经历自然流淌，再收敛到结构里
2. 因果大于枚举——不要只列"做了什么"，要写"什么导致了什么"
3. 判断列不能省——完成的表格里必须有评估符号（符号表见「固定板块」），数据不评估就是废数据
4. 每条改进对应一条根因——不凭空想"明天要怎样"，从今天的问题里长出明天的行动

### 反思分流：复盘如何回流知识库

每次日复盘后可以提醒用户，有哪些可以总结提炼，按以下规则分流，用户同意后，才能执行，不得没经过同意就自己总结这一部分内容

| 反思内容          | 去向        | 操作             |
| ------------- | --------- | -------------- |
| 清晰认知，零散不属任何体系 | 常青笔记 `#识` | 新建笔记，双链回指当日日志  |
| 清晰认知，属于某个学习体系 | 系统笔记      | 补充到对应系统笔记，双链回指 |
| 模糊知识性思考 | 待处理笔记/随笔 | 记入 `个人迭代/待处理笔记/随笔/`，双链回指当日日志 |
| 行动的想法 | 起念        | 记入 `起念.md`     |

**关键规则**：所有分流产出必须用 `[[当日日志]]` 双链回指，保持可溯源。

## 七、每日任务推进HTML看板

> 「每日任务推进」HTML 看板 = 明天的工作台（2026-10-13 建成）。当晚总结写完「明日任务」（含定级落笔）后，就能一键把今天的日志滚成明天的看板——扫描全自动，子任务拆解留给 AI。
>
> 日常操作只记两件事：浏览器弹「允许读取」时点一下允许；再选好生成位置（建议存桌面）就行——其余全自动。

### 入口：两种开法

| 开法 | 怎么做 | 什么时候用 |
|------|--------|-----------|
| 打开之前生成的看板 | 双击最近一份「每日任务推进.html」→ 点右上「**新一天 ⟶**」 | 日常——每份看板都自带完整生成器 |
| 从模板生成 | 双击 `模板/HTML模板/每日任务推进_种子模板.html` → 同样点「新一天」 | 链条断了（看板文件删了 / 换机器），种子不依赖任何一天的文件 |

点「新一天」后它会自动找今天的日志：授权过日志文件夹的浏览器静默自动读；首次使用（或该浏览器文件夹授权不可用）会弹文件框——选中今天那份 `YYYY-MM-DD.md`（文件名要对上），再在保存框确认明天的文件（默认「X月X日_每日任务推进.html」，建议存桌面）。生成后明天首开会自动进仪式。

### 扫描对应：日志哪里进看板

| 日志里的位置 | 看板里变成 |
|--------------|-----------|
| 「### 明日任务」标题里的「明日状态：X级」 | 明天的级别 → 自动带出对应固定量清单 |
| 「明日任务」区的增量行（`- [ ] 增量N：文字 📅 明天`） | 「增量」清单条目——生成时全部先落"待拆解"，只在总览出现 |
| 「### 改进」区的勾选项 | 仪式第二步「今日改进」（📅 剥掉） |
| 日志没写 / 没定级 | 生成被拦下，按提示先补 |
| 明日无增量 | 不拦——照常生成，看板与仪式显示「今日无增量」（2026-10-13 拍板：零增量日合法） |

- **缺天不补**：永远扫真实今天的日志、生成明天；漏掉的那天不回补，要补内容找 AI 从当天的日志重建。
- **零继承**：生成物只含日志里的东西——今天没做完的任务不会自动带进明天，要延续就跟 AI 说一声，把旧看板数据块里的板块搬进新文件。

### 首开仪式：四步过一遍

新看板每自然日第一次打开会触发四步全屏向导：**定级 → 今日改进 → 快速增量 → 增量与子任务**，每步只有一个确定键——仪式的意义是开工前把当天有什么过目一遍（隔天打开旧文件不会触发；`?wiz=N` 可强制重播）。

- **定级卡直接选规定好的**：日志定的那级带「昨夜已定」徽章，确定即可。**为什么最好别改选**——定级的唯一事实源是当天日志「明日状态：X级」；仪式里点别的卡只换这一页面的固定量显示，刷新即还原、也不写回日志，第二天滚日认的还是日志。真要改级别：改日志。
- **复杂增量在这里和 AI 拆解**：日志里增量只是一句话（复选框是日志侧归集完成用的），看板里可以再拆——跟 AI 说一声，把子任务拆解丰富进看板数据块，总览清单就长出逐项子任务，做完逐项勾选（勾选存浏览器本地）。生成时所有增量都落"待拆解"，一句话的小事让 AI 挪进快速增量区，系统任务配子任务板块。
