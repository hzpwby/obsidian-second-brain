# 脚本层与语义层

## 核心观点

**和 AI 协作的任何一个产物，都按「对错能不能在事前定死」切成两层。** 定得死的（结构、字段、命名、骨架、排版）在生成之前就用模板和约束框死，AI 照填执行、不许发挥，越界即报错；定不死的（内容、讲法、判断）给规范让它批量发挥，人工审查收口。**开工先切层，切错整轮白干。**

## 详细内容

### 判据：钉在裁决侧，不钉在执行侧

- 分层看的是**谁给出裁决**，不是谁动手——审计脚本跑的和 AI 填表被 schema 框死的同属一层，共同点是判定不依赖人的判断。
- 这条线本身是客观的：逻辑数学式的（对就是对、错就是错）归脚本层，语文式百家争鸣的（没有唯一答案）归语义层。
- **判据不动，落点会动。** 某一类判断今天落在语义侧，等给它写出可判定标准，它就归脚本侧。迁移触发：**每轮人工审查结束时问一句——这轮里我重复做了哪几次同一类判断？** 重复的判断＝下一个该框死的东西。**语义层是脚本层的原料，不是并列的另一堆。**

### 分拣单位是字段，不是任务

两层在同一个交付物里**叠加**，不是二选一。一张卡：tags 段位、板块顺序、标题层级可机判 → 脚本层；引入是否闭环、讲法对不对 → 语义层。所以动作是"切它"，不是"猜它属于哪类"——纯脚本任务与纯语义任务只是某一层占满的特例。

### 时机 × 层：四格

|      | 脚本层（机器裁决）          | 语义层（人裁决）           |
| ---- | ----------------- | ----------------- |
| 生成端 | 事前框死：模板、约束、落盘钩子   | 给规范和边界，AI 批量写     |
| 审查端 | 全量扫确定性检查项，同款模式批量改 | 逐条判、附理由，人对照裁决     |

- 生成端语义层的产物走两道：**AI 语义审 → 人审**。
- **框死管未来，追溯管存量。** 新增规范落地时，存量产物早在该规范存在之前就生成完了。同一件规范挂在脚本侧＝一条命令＋一次批量改；挂在语义侧＝全库逐条重审。**这条决定了新规范该往哪写。**

### 怎么框死：按拦在哪一环排

| 拦在哪   | 手段                                       | 效果                            |
| ----- | ---------------------------------------- | ----------------------------- |
| 生成前   | **模板渲染**（knap：JSON/CSV＋模板→批量 markdown）   | 必填项缺了根本填不出来，骨架违例归零             |
| 生成前   | **schema 校验**（结构性字段以 JSON 交付，解析失败＝拦下重填） | 静默的格式错误变成响亮的失败                 |
| 生成中   | **受限解码**（API strict 模式 / structured outputs） | 每个 token 把不合法候选置零，坏结构数学上写不出     |
| 落盘时   | **钩子（hook）**：每次写入自动跑预挂判据                 | 不合格当场打回，一次都不许带病进门（**库里尚未启用**） |
| 全量事后  | **审计脚本**：扫全库出确定性清单                        | 能查出、能追溯新规范；代价是永远慢一拍            |
| 最后    | **人**                                    | 判据写不出来的那一侧，只能在这里               |

取舍看**代价**不看强弱：前三格换来免审资格，但要你先把判据写出来；第四格当天就能上；第五格最贵，也是唯一能处理"没有标准答案"的一格。

### 语义层不是没有规范

- **规范不是分层的判据，两层都要给**，区别只在谁裁决。语义层照样有硬规格：字段数固定、每项必附判断理由、改法给**成品式**（改后的完整文字，与原文并排即可对照；禁"把 X 改为 Y"式纯指令）。规格的作用是**把人的裁决成本压到一次扫读**，不是把语义问题伪装成格式问题。
- 规范的制定归思考端，执行端不许自己改框架（[[一个模型思考，一个模型执行#操作约定]]）。
- 语义层要留出发挥空间：正文长文本硬塞进 schema 有创作损耗，宁可自由文本写完再拼装。

### 免审资格

> **审查能不能不管这一块，取决于它有没有被真隔断在源头，不取决于它看起来多机械。**

- **已隔断**（程序渲染、约束不过就写不出）→ 免**形式**审，并写明"因为哪条管线免审"。
- **未隔断**（靠模型自觉＋事后检查）→ 必须审，这一侧的检查项是免审资格的唯一来源。现行链路多在这一格。
- **每一层只免除它自己那一维**：框死免除形式审，内容审照做。带着"已过机器关"可信度的内容错误，比没框死的更难被人怀疑。
- **真免审只有一种**：整件事既无内容亦无判断——纯渲染、纯搬运、纯转换（例：[[本地PDF批量转md（MinerU）]]）。
- 想把一类问题从"要审"降到"不审"，办法是**把它搬进确定性管线**，不是把它归类为"应该没问题"。

### 配套闸门

- **批量修必须逐处判定**：同款字符串会撞上照录区、文件名、独立题面这类不该改的位置——模式相同不等于可盲替换。
- **脚本要收口对账**：报 N 条改 N 条，修完复跑至归零或逐条落豁免，不重扫全量。
- **框死者本身要审**：模板、schema、判据都是人写的一次语义判断，改动走人审，唯一事实源留在对应框架文档。

### 边界

- 分层与判据的成本在**开工前**付；一次性小任务别建管线（[[盖尔定律#核心观点]]——先跑简单闭环再长模块）。
- 判据写不出来就别硬写：伪约束只会把语义问题伪装成格式问题，绿灯更多而错误没少。
- 工具会换、模型会换：本篇的价值在**切法**，不在任何具体 CLI。
