PART 1 · 部分一

固定与可变 · 总账

套模板前先分清哪些不能动、哪些随便换——这一页所有「占位」字样都是换内容的地方。

固定与可变的分账
  • 固定的（骨架，不要改）：色调 UI、顶部板块页签流转、左栏双层目录、右栏壳、快捷键 ← / → / Esc、层级结构（板块→部分→小节）与各级标题样式、状态标记；
  • 每次要填的（内容）：板块名、部分名、小节名、全部正文；
  • 加层级的固定动作：见下方「加板块 / 加部分 / 加小节」数据流卡——id 对上，跳转/高亮全自动。
加板块 / 加部分 / 加小节的固定动作
加板块（顶部页签 + 整块面板）： 顶部 <nav id="tabs"> 加一个 .tab（data-panel="pN"） 主区加 <section class="panel" id="pN"> 左栏条目都标 data-panel="pN" 加部分（板块内一节）： 主区 <section class="chapter" id="pN-aM"> + 左栏 <a class="side-link"> 加小节（部分内一层，最多嵌套这层）： 标题 <h3 class="mini" id="pN-aM-sK"> + 左栏 <a class="side-sub"> ← id 对上即可，JS 不用改

内容组件与状态

写正文用的所有卡片部件都在这里——需要什么取什么，文字全部由项目填。

内容卡与状态标记

内容卡 · .card + .tag + .role + ul.pts

一句话说明条（.role）——概括这张卡片讲什么。

  • 普通条目：正文占位——em 是青色强调，关键处加粗变琥珀。
  • 状态条目（li.ok ✓）——已完成 / 已确认的事。
  • 状态条目（li.wip △）——进行中的事。
  • 状态条目（li.todo ◇）——待办 / 未完成的事。

状态标记是固定组件，有需要就取用：▸ 普通 · ✓ 完成 · △ 进行中 · ◇ 待办——换 li 的 class 即可，文字全部由项目填。

PART 4 · 部分四

两个预设怎么套用

板块二、三、四是写好的起跑线——选贴近需求的那个，把「占位」逐个换成自己的内容即可。

二
预设 · 产品说明

结构：总览与设计哲学 → 产品大致结构 → 说明的板块地图 → 各功能板块详解（每个功能板块固定三讲：定位 → 结构 → 使用与 DIY）。适合介绍一个产品/工具/系统。

三
预设 · 项目推进

结构：任务总览勾选 → 执行顺序与要点 → 各任务详情板块（子任务四要素）。适合独立想法、长期项目、梳理思路——顺序是预估推进，要点自己填。

套用口诀
  • 先逛板块一：认识每个部件长什么样、在哪改；
  • 再挑预设：介绍产品用板块二，推项目用板块三，都不贴就照板块一的部件自由拼；
  • 最后整体换内容：选定的预设板块（其余板块删掉或留作说明）里所有「占位」逐个替换——骨架永远不用动。

PART 1 · 部分一

总览 · 定位与设计哲学

开篇总览：这个产品是什么、为什么做、给谁用、背后相信什么。

定位与哲学卡 · 占位

一句话定位——「产品名」是给谁、用来做什么的。

  • 现状：没它之前，是怎么样的？痛点是什么样的；
  • 如何解决：它具体是怎么解决这些痛点的；
  • 给谁用：适用对象、什么时候用；
  • 设计哲学：产品的取舍与相信——为什么长这样而不是那样。

整体结构 · 占位

  • 组成说明：每一块是干什么的、边界在哪；
  • 配合关系：数据/流程怎么在组成之间流转。

说明的板块地图

给读者的导读：本说明设立了哪些板块、每个板块讲什么、按什么顺序读。

板块地图 · 占位
板块一 总览（定位与设计哲学 + 产品大致结构） ▼ 先认识它 板块二 安装与设置 ← 可选板块：产品需要搭环境才写；没有就跳过，直接读板块三 板块三往后 各功能板块详解（一个功能板块讲一个部分） ▼ 每个功能板块内部固定三讲 第一讲 定位（解决什么、有什么用） 第二讲 结构（文件结构 / 数据流转结构） 第三讲 使用与 DIY（怎么用、哪些地方可以自定义）
  • 怎么用这张地图：按顺序读即可；赶时间可跳过可选板块，直接进功能板块；
  • 套用提示：板块数量由产品决定——地图上有几个板块，说明就挂几个板块页签。
PART 4 · 部分四

功能板块的内部模板

板块三往后的每个功能板块都长这样——三讲固定，内容各填各的。

一
第一讲 · 定位

这个小部分是干什么的、解决的东西是什么、有什么用——先说清存在的理由。

二
第二讲 · 结构

它的结构：文件结构、数据流转结构或其他组成——用 .dataflow 画树最直观。

第三讲 · 使用与 DIY（内容卡示范 · 占位）

一句话说明条——这个小部分日常怎么用。

  • 基本用法：操作步骤占位；
  • 进阶用法：组合技巧占位；
  • 可以 DIY 的地方：哪些参数/样式/结构允许按需改；
  • 常见问题：卡住时怎么办。

PART 3 · 部分三

执行顺序与要点

总览之后先定推进设计——顺序是预估不是死表，要点是干法与坑，全部由项目自己填。

执行顺序 · 预估推进
任务一 ——预计什么时候完成什么事（占位） ▼ 预估推进的进展 任务二 ——预计什么时候完成什么事（占位） ← 都是预估：大概的节奏，不卡死时间，推进中随时改
执行要点 · 怎么干
  • 要点占位一：这件事具体怎么干；
  • 要点占位二：干的过程中注意什么；
  • 容易踩的坑：提前写下来提醒自己。
任务详情板块 · 每个任务拆一个

子任务四要素 · 详情板块模板

板块一只管勾选；任务的详细推进拆到独立板块（套用后：板块二=任务一详情、板块三=任务二详情……）。每个子任务按四要素展开，详情板块不放勾选。

子任务四要素卡 · 占位
  • 要完成什么：这个子任务的产出占位；
  • 现状：手头上有什么资料、什么资源；
  • 目标：做到什么样算完成——要可验收；
  • 预估时间：大概多久、截止什么时候。

顺序固定：要完成什么 → 现状 → 目标 → 预估时间；一个子任务一张卡，做完回板块一勾掉。
