# 每日复盘（对话收敛式晚间总结）

陪用户完成当天日志的「每日复盘」区：口述 → 扫描整理 → 一次一问收敛 → 收尾 → 落笔自查。

**本 skill 只是执行手册。**所有规则细节——写作结构、固定/按需板块要求、反思分流表、定级落笔规则、落笔后自查清单——的唯一事实源是《复盘迭代框架》§六（`框架/复盘迭代框架.md`）。**每次执行先读该节；缺什么规则去框架里查，绝不凭记忆编造，也不把规则复制进本文件**——用户改规则只改框架，本 skill 永远自动跟随。

## 流程

### 1. 口述（触发即口述）
用户选本 skill 或说"总结一下今天"这类话触发时，消息里就直接说今天干了什么——想到什么说什么，长、跳跃、口语化都行，没有"边听边记"：用户的消息没发出来之前 AI 什么都不知道，收到后直接进入第 2 步。白天的信息流积累（平时随手发给 AI 的内容）在口述里一起并入。日志里能查到的事实（已勾/已填）AI 不反问"做没做/是多少"。

### 2. 扫描＋整理（口述信息收集完后）
此时才对照口述内容扫描，再合并"用户口述＋扫描所得"处理：

- 扫描：读今天的日志 `日志/日复盘/{今天日期}.md`，逐板块核对已填/未填（板块结构以日志模板为准），已填的不问；跨文件搜 `📅 {今天日期}` 的任务行与勾选状态（主要在昨日日志「改进」「明日任务」区，也可能散在待办文件；顺带记录 📅 早于今天且未勾的逾期项）
- **提醒完善**：用户没说、日志里也没有的固定板块内容和数据缺填，一部分一部分提请用户补上；已勾的不问"做没做"，只追问漏做原因
- **询问增补**：按当天情况对照框架§六「按需板块」，建议加的逐个问"需不需要"；现有板块（固定＋按需）都装不下的新东西，问用户要不要今天新加一个板块

### 3. 一次一问收敛
- **一次只问一个问题**：等用户回答后再问下一个，绝不在一条消息里塞多个问题——同时抛多个问题会让人无所适从
- **每个问题都附上你的推荐答案**：让用户可以直接接受、否决或修正，不用从零想
- 固定板块一一对应过清单，缺哪块问哪块（固定/按需板块清单见框架§六「每日复盘写作结构」）
- 追问**原因和判断**（漏做的为什么、判断列评了没、哪句逻辑站不住），不是事实复述
- 持续追问直到五段都有着落、双方达成共识——没收敛完不进入落笔

### 4. 收尾
- 定级仪式两问：①明天几级？②明天的增量是什么？——落笔规则见框架§六「明日任务」行
- 反思分流提醒：今天有没有值得升格的，**用户同意才执行**——分流表见框架§六「反思分流」节

### 5. 落笔＋自查（共识即确认）
- 共识达成后直接写入今天日志「每日复盘」区；改进/明日任务行带 `📅 明天日期`（次日自动归集进「今日任务」）
- 落笔后自查：模板占位（「改进项1/2」、空「明日任务」行、各板块「（记录今日…）」括号占位）全部替换或删除，不得残留重复板块或假任务（带 📅 的占位会进 Tasks 看板变成僵尸任务）；回读一遍结构——健身表格在健身标题下、菜谱在健身后、五段完整不重复
- 收尾汇报：写了什么＋自查结果

## 禁忌

- 一次一问，绝不连抛多问
- 事实自己查，决策等用户：能扫描到的事实不问用户；涉及取舍的决策摆到用户面前等拍板，绝不替用户做未经确认的决策
- 日志已勾/已填的一律不问"做没做/是多少"，只追问原因与判断
- 规则细节一律现场查框架，不凭记忆、不复制进本文件
- 共识确认前不落笔；反思分流未经用户同意不执行
