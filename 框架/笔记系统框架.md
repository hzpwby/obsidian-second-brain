## 一、笔记框架文件架构

```
个人迭代/
├── 待处理笔记/          ← 收件箱（外部输入专用）
│   ├── 网站爬取/        ← Bilibili/Obsidian Clipper 剪藏字幕和网页
│   └── 随笔/            ← 模糊知识性思考
├── 常青笔记/            ← 零散认知碎片，每篇一个 .md
│   ├── 盖尔定律.md
│   └── ...
├── 系统笔记/            ← 体系化知识网络，每领域一个子文件夹
│   ├── AI使用/
│   └── ...
└── 笔记目录/            ← Bases 管理入口
    ├── 待处理笔记.base   → 一级入口
    ├── 待处理笔记目录/   ← 二级 .base
    │   ├── 网站爬取.base
    │   └── 随笔.base
    ├── 常青笔记.base
    ├── 系统笔记.base
    └── 系统笔记目录/     ← 二级 .base，每领域一个
        ├── AI使用.base
        └── ...
```

> 具体文件列表以实盘为准。AI 操作时先读取` 个人迭代/` 最新目录结构，不以本框架中的静态示例为准。

**Bases 联动逻辑**：`笔记目录/` 采用两级 `.base` 结构。一级 `.base` 提供统一入口，其中 `待处理笔记.base` 和 `系统笔记.base` 分别指向各自的二级 `.base` 目录（`待处理笔记目录/`、`系统笔记目录/`）。

| 层级  | .base                | filter 指向           | 展示内容              |
| :-: | -------------------- | ------------------- | ----------------- |
| 一级  | `待处理笔记.base`         | `个人迭代/笔记目录/待处理笔记目录` | 按类型分组的二级 .base 入口 |
| 二级  | `待处理笔记目录/网站爬取.base`  | `个人迭代/待处理笔记/网站爬取`   | 网站爬取笔记            |
| 二级  | `待处理笔记目录/随笔.base`    | `个人迭代/待处理笔记/随笔`     | 模糊知识性思考           |
| 一级  | `常青笔记.base`          | `个人迭代/常青笔记`         | 所有常青笔记            |
| 一级  | `系统笔记.base`          | `个人迭代/笔记目录/系统笔记目录`  | 按领域分组的二级 .base 入口 |
| 二级  | `系统笔记目录/AI使用.base` 等 | `个人迭代/系统笔记/领域名`     | 该领域下的系统笔记         |

## 二、三类笔记定位

| 类型    | 定位   | 目录               | 说明                            |
| ----- | ---- | ---------------- | ----------------------------- |
| 待处理笔记 | 收件箱  | `个人迭代/待处理笔记/`    | 外部信息入口（网址、视频、素材），模糊知识性思考想法在随笔 |
| 常青笔记  | 零散认知 | `个人迭代/常青笔记/`     | 提炼后的认知碎片，一篇一个观点。靠双链互相连接       |
| 系统笔记  | 体系网络 | `个人迭代/系统笔记/领域名/` | 系统学习一个领域的知识网络。按领域建子文件夹        |

**判断标准**：这个认知属于某个学习体系吗？
- 不属体系 → 常青笔记（例："不成体系但经典的世界观、方法论"）
- 属体系 → 系统笔记（例："Obsidian 的 Tasks 插件用法"属于 obsidian 插件教学体系）

## 三、待处理笔记使用说明

> 两个子系统：随笔（模糊知识性思考）和网站爬取（剪藏字幕和网页）。

### 随笔

对某个概念、现象、方法的模糊认识——还没想清楚，但值得先记下来。不整理、不归类、不追求格式。后续在笔记成熟路径中逐渐沉淀。

操作：在 `个人迭代/待处理笔记/随笔/` 下新建笔记。格式自由，建议至少写一句话核心观点 + `--` 分隔线 + 上下文（为什么有这个想法）。

### 网站爬取

B站视频用 Bilibili Obsidian Clipper 爬取字幕。内容统一保存到 `个人迭代/待处理笔记/网站爬取/`。爬取后 Agent 读取原件进行 AI 总结。

#### Bilibili Clipper 配置

1. Obsidian 端：安装并启用 `Local REST API with MCP` 插件，勾选 `Enable HTTP Server`（默认 `http://127.0.0.1:27123`），复制 API Key
2. 浏览器端：打开 Bilibili Obsidian Clipper 扩展设置，填入 API 地址和 Key，保存路径设为 `个人迭代/待处理笔记/网站爬取`
3. 使用：打开 B站视频 → 点扩展图标 → 爬取字幕

详细配置见 [[Local REST API插件]]。

> **不需要异常处理**：Bilibili Clipper 爬取失败重试即可。

## 四、笔记成熟路径

```
外部输入                    复盘反思产出
   │                           │
   └──────→ 待处理笔记 ←────────┘
                │
         提炼/完善（定期回顾）
                │
         ┌──────┴──────┐
         ↓              ↓
    常青笔记          系统笔记
    （零散认知）      （属某体系）
         │              │
    ┌────┴────┐    与常青笔记双链
    ↓         ↓
  #识       #道
（新知）    （规律）
    │
 实践验证
    │
    ↓
  #道       ──拆解──→  #术
（稳定沉淀）          （操作方法）
```

### 关键节点

| 节点      | 触发条件                | 操作                           |
| ------- | ------------------- | ---------------------------- |
| 入待处理    | 看到好文章、外部素材          | 在随笔或者网页爬取文件夹下，快速写入           |
| 入常青     | 待处理笔记里的想法能提炼出一句核心观点 | 用常青笔记模板写入，标 `#识`，原待处理可删      |
| 入系统     | 待处理或常青的内容属于某个学习领域   | 写入对应领域的系统笔记，与常青双链            |
| #识 → #道 | 该认知经过多次实践验证，证明稳定有效  | 把 `#识` 标签改为 `#道`             |
| #道 → #术 | 想把这个规律变成可操作的方法      | 写一篇新的带 `#术` 标签的笔记，回链` #道 `笔记 |

### 标签概念：识 → 道 → 术

| 标签 | 含义 | 何时使用 | 示例 |
|------|------|---------|------|
| `#识` | 阶段性认识 | 刚提炼出来，还没经过充分验证。可能是对的，可能偏 | "AI 幻觉可以通过喂一手信息降低"（刚有想法，试了几次有效） |
| `#道` | 根本规律 | 经过多次实践反复验证，稳定成立 | "盖尔定律：复杂系统从简单系统演化而来"（公认原则） |
| `#术` | 实践方法 | 从道或识推导出的可执行步骤 | "给 AI 喂原始资料，不让它凭空回忆——三类一手信息：源码、截图、官方文档" |

**常见问题**：

| 问题         | 回答                                                      |
| ---------- | ------------------------------------------------------- |
| 什么时候从识升道？  | 至少在不同场景下验证过 2-3 次，且每次都成立。可以提醒用户到了时机，但不主动代用户升级。不急升级，宁可多挂一段`#识` |
| 识发现是错的怎么办？ | 不改标签。在原笔记下方加"修正"段落，保留原始内容。这是认知迭代的证据                     |
| 什么时候写术？    | 当你需要一份可操作的步骤清单、检查清单、流程图时。不是每个道都需要术                      |

## 五、模板

### 待处理笔记模板

| 子类型 | 模板 | 目录 | 说明 |
|--------|------|------|------|
| 随笔 | `模板/随笔模板.md` | `个人迭代/待处理笔记/随笔/` | 模糊知识性思考，格式自由 |

> 网站爬取不再使用模板——Bilibili Clipper 按插件内置格式直接写入，无需模板干预。

**随笔模板**（`模板/随笔模板.md`，单一事实源——框架不内嵌模板全文）：

格式自由。建议至少写一句话核心观点 + `---` 分隔线 + 上下文（为什么有这个想法）。

### 常青笔记与系统笔记模板

两者共用同一模板：`模板/常青笔记与系统笔记模板.md`（单一事实源——框架不内嵌模板全文）。

**标签规则**：
- 仅常青笔记和系统笔记使用 `#识` `#道` `#术`
- 模板、日志、框架、待办等其他笔记一律不加
- 可以从两个标签开始（如先标 `#识`，验证后加 `#道`）

## 六、执行操作

### 新建笔记用的模板与位置

| 场景          | 模板          | 存放位置                  |
| ----------- | ----------- | --------------------- |
| 从待处理提炼出认知   | 常青笔记与系统笔记模板 | `个人迭代/常青笔记/标题.md`     |
| 学习新领域，需要体系化 | 常青笔记与系统笔记模板 | `个人迭代/系统笔记/领域名/标题.md` |
| 复盘反思产出      | 常青笔记与系统笔记模板 | 根据性质选常青或系统            |
### 新建笔记内容格式

**写作原则**：

- **精炼**：每句话必有信息量。写完删一轮——任意一句删掉意思不变就删。
- **先结论后论证**：开门见山给核心观点，再展开。不让读者猜"这篇想说什么"。
- **一层一事**：一个段落只讲一个意思。不在一段里塞多个观点。
- **关键加粗**：核心概念、判断标准、重要结论用 `**加粗**` 标记。扫读时粗体字形成独立信息流。

**各板块写法**：

| 板块 | 写法 | 示例 |
|------|------|------|
| **核心观点** | 一句话概括。结构：「是什么」+「为什么重要」 | "盖尔定律：复杂系统必须从简单系统演化而来。过度设计是认知成本最高的错误。" |
| **详细内容** | 论证/解释/示例。从核心观点逐层展开。可用 `>` 引用块标记关键论述 | > 你从一个简单但能运转的系统开始，再逐步添加模块 |
| **来源** | 自己的想法 → 写"自己"；参考文章/书 → `[[书名]]` 或 URL | `[[小岛经济学]]` / 自己 |
| **关联笔记** | 已建立的笔记用 `[[]]`，默认指向具体章节锚点（如 `[[笔记名#节标题]]`）；未建立的用纯文本 +（待建立），避免空链接 | `[[盖尔定律#核心观点]]` / 奥卡姆剃刀（待建立） |

**标签规则**（详见 [[#标签概念：识 → 道 → 术]]）：
- 新建笔记默认标 `#识`，经实践验证后升级为 `#道` 或拆解为 `#术`
- 不建议建笔记时一次标多个标签，先确定阶段再标

**命名规则**：
- 常青笔记：`{核心观点}.md`，如 `盖尔定律.md`、`减法是更高级的构建.md`
- 系统笔记：`{领域名/标题}.md`，如 `AI使用/提示词设计.md`

### 双链维护

**操作时机**：

| 时机 | 操作 |
|------|------|
| 新建笔记时 | 在"关联笔记"板块写相关笔记链接 |
| 浏览旧笔记时 | 发现新的关联，顺手在旧笔记也补上链接 |

**方向规则**：

```
A 提到了 B → 在 A 的「关联笔记」中加 [[B]]
         → 如果 B 也应该知道 A，回头在 B 也补上 [[A]]
```

一个相关性不一定双向。双向补链实事求是——确实有关联才补，不可强行连接。

**空链接处理**：
- 新建时：尚未建立的笔记用纯文本 +（待建立），不创建空链接（避免 Obsidian 灰链降权）
- 维护时：发现（待建立）标记对应的文件已存在，替换为 `[[文件]]`

**孤岛笔记**：新建时检查该笔记确实没有可关联的笔记，就不用强行连接。孤岛就孤岛，不需要定期排查。
